# 【mysql】索引页分裂和合并
在 InnoDB 中，索引页是负责存储索引节点数据的，索引页通过 B+ 树结构快速定位数据。每个索引页通常大小为16KB，其通常可以存储多个索引节点并且是有序的，通过指针与其他页进行连接。

索引页分裂指的是当一个索引页的容量达到上限时，再插入数据会导致该页无法容纳更多的数据，这时数据库会自动将该页分裂成两个页。通过分裂，数据会被平衡分配到两个页中，从而保证 B+ 树的平衡性和查询效率。

索引页分裂的过程：找到第一个数据页中间的位置，大于中间的部分移动到新开辟的数据页当中，插入的数据会优先插入到当前页。

索引页合并：当索引页中的索引数据删除后，索引页可能会变得过于稀疏，为了节省空间和提高性能，会触发索引页合并操作。

索引页分裂与合并的坏处：
* 其会涉及大量数据移动和重组的操作，会增加数据库的IO负担和CPU消耗，影响数据库的整体性能。
* 其会导致 B+ 树索引结构频繁的调整，这时也会影响插入及删除操作的性能。

可通过以下方式来减少索引页分裂与合并：
* 使用自增主键ID：由于索引页的数据是有序的，所以在插入时会按照顺序找到合适位置进行插入。例如：假设每个索引页最大能存储四个数据，当前有A和B两个索引页，都是无序插入，A已经存储了1、2、4、5这四个数据，B已经存储了6、8这两个数据，此时需要插入数据3的话就会导致索引页A的页分裂；如果是按顺序插入的话，A已经存储1、2、3、4，而B已经存储5、6，此时需要插入数据7的话就只需要插入到索引页B即可，不会导致索引页分裂。所以主键ID尽量选择使用自增ID（在数据库迁移时，可以在新库中设置自增初始值），而不是UUID或雪花ID。
* 尽量使用批量插入：每个批次内的插入操作都可能集中到同一个页中，减少了页的分裂频率。
* 使用逻辑删除而不是物理删除：频繁删除操作可能导致页面过于稀疏，从而触发索引页合并。
